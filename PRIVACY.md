# Privacy

Open Diagnostic Lab is designed for **self-hosted** use by a single diagnostic center.

## Data ownership

- Patient demographics, orders, results, and reports are stored only in the PostgreSQL database you run (by default a Docker volume on your host).
- The default build does **not** include telemetry, analytics SDKs, crash reporters, or any phone-home network calls.
- Project maintainers never receive your clinic data unless you deliberately share logs or backups with them.

## What the application stores

- Staff accounts (username, password hash, role)
- Patient details needed for lab workflow and printed reports
- Referring doctors and test catalog
- Orders, measured values, and audit fields (who last updated results)

## Operator responsibilities

You (the clinic / host operator) are responsible for:

- Keeping the host, Docker images, and secrets secure
- Restricting network access (LAN / VPN / firewall)
- Enabling HTTPS in production and setting a strong `SECRET_KEY` and admin password
- Backups, retention, and lawful deletion of patient data
- Compliance with local health-data regulations (this software does not by itself certify HIPAA, DISHA, GDPR, etc.)

## No secondary use

Contributors and distributors of this open-source software make no claim on patient data generated by your deployment. Do not configure third-party cloud databases or logging pipelines unless your organization has reviewed those vendors’ privacy terms.
